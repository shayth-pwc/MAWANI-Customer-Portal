# Mawani Customer Portal v0.7.4 — IAS updates, PostgreSQL synchronization and safe provisioning

## Scope and status

Implemented and tested **offline**. No live Cloud Foundry deployment or live IAS SCIM update was performed while preparing this package. Use the dedicated test account and inspect the live SCIM response after deploying.

The release preserves existing MTA module names, Cloud Foundry routes, IAS bindings, PostgreSQL service instance, existing physical tables and the v0.7.3 `createIasUser`/`syncIasUserToPortal` contracts. No DB migration or service provisioning is required.

## Changes

1. `POST /admin/updateIasUser`: SCIM PATCH now sends an atomic complex `name` replacement (preserving other name components) when givenName/familyName is supplied; validates actual `name.givenName`, `name.familyName` and primary email values with a fresh raw SCIM GET. On a mismatch, returns HTTP 503 `IAS_RESULT_UNCERTAIN` and **does not synchronize the portal**. No automatic retry of remote PATCH.
2. On a **verified** IAS update, synchronize only the changed IAS-sourced attributes (`EMAIL`, `FNAME`, `LNAME`) to the corresponding PostgreSQL portal record, in a DB transaction that includes `PORTAL_USER_IAS_SYNC` and `IAS_USER_UPDATE` audit rows. Preserve local-only fields such as `ACCOUNT_TYPE`, telephone, issuer and subject.
3. `POST /admin/setIasUserActive`: verify the returned SCIM `active` state before applying `ACTIVE_STATUS` to the portal row; commit with audit. **Explicit** administrator activation can change local status, but ordinary sign-in never reactivates a disabled local profile.
4. `POST /admin/reconcileIasUserToPortal` accepts `{ "id": "<IAS SCIM ID>" }`. It independently fetches the IAS user and deliberately reconciles **all** four IAS-sourced portal attributes including active state. It is an administrator-only recovery action when remote IAS changed but local storage did not. Unlike the existing create-only `syncIasUserToPortal`, it is designed to overwrite these attributes. Do not call it on locally disabled users without intending to restore the IAS-reported state.
5. `GET /profile/me()` is read-only. It verifies IAS token identity and IAS directory status and reads the profile without INSERT, UPDATE, identity linking, transaction locks or audit writes. A missing local profile yields HTTP 404 with guidance to use POST.
6. `POST /profile/provision` (no arguments): idempotent, authenticated and CSRF-protected; maintains existing first-login behavior including IAS verification, advisory lock, profile creation or identity linking, audit transaction and local inactive-profile checks.
7. Authenticated router `/` now serves a minimal static bootstrap page which automatically fetches CSRF, sends `POST /profile/provision`, then fetches the read-only profile. This temporary page is to preserve automatic first-login behavior until the Phase 2 React application is deployed. **Router root is now HTML, not JSON.** Direct API clients should call `GET /profile/me()` or `POST /profile/provision` instead.
8. Administrator authorization is still verified by IAS SCIM membership in the configured group; if a local row exists, check *both* IAS ID and issuer/subject linkage so a disabled pre-linked administrator row cannot bypass local restriction. Read-only administrator calls no longer auto-provision.
9. The IAS `displayName` literal `None` is treated as a placeholder if SCIM `name` fields are available.
10. `node scripts/admin-audit-verify.js <IAS_ID>` performs a read-only action/status summary for the test IAS identity and its portal UUID.

## Cross-system failure handling

IAS and PostgreSQL **cannot share a transaction**. After SCIM PATCH has succeeded and is verified, a PostgreSQL read/write/audit failure yields HTTP 503 and the message that IAS may already be changed, with instruction to call `reconcileIasUserToPortal`. Do **not** automatically repeat the IAS PATCH, and do not delete the remote identity to compensate. A best-effort `UNCERTAIN` audit is attempted.

If SCIM PATCH returns success but a raw SCIM GET does not show the requested attributes, the action reports `IAS_RESULT_UNCERTAIN`. The portal row is **not** modified. Verify the raw directory state with an administrator before retrying or reconciling; an eventually consistent SCIM provider may need time to surface updates.

## Deployment (SAP Business Application Studio)

Extract package into the existing project, **without deleting local `.env` or changing Cloud Foundry secrets**. Check that the workspace has `package.json` version `0.7.4` and MTA version `0.7.4` before building.

```bash
cd /home/user/projects/mawani-customer-portal-phase1-configured
npm install
npm run check
npm test
node test/qa-browser-v074.mock.cjs
mbt build
python3 scripts/verify-mtar.py mta_archives/mawani-customer-portal-backend_0.7.4.mtar
cf target -o mawani-btp-dev -s mawani-btp-dev-SP
cf deploy mta_archives/mawani-customer-portal-backend_0.7.4.mtar
cf apps
cf tasks mawani-portal-srv
```

Do not use `cds deploy` or recreate database tables. After deploy, ensure existing IAS SCIM technical credentials are still configured without printing their values. Roll back by redeploying the retained v0.7.3 MTAR if needed, recognizing that v0.7.3 had side-effecting GET behavior.
